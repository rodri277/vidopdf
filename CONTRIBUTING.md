# Contributing

Thanks for helping. Vidopdf is free software under the [MIT license](LICENSE); by sending a contribution you agree it is published under that license, and you confirm that you wrote it or have the right to submit it (no code copied from projects with an incompatible license, no private documents in tests).

## Before you start

- Read [SPEC.md](SPEC.md) and [CLAUDE.md](CLAUDE.md): the architecture rules (a DOM-free `core`, pdf libraries only in workers) are enforced by `pnpm lint`.
- Open an issue for anything bigger than a small fix, so the idea can be discussed first.
- A new dependency needs its license checked against the allow-list (`pnpm licenses:check`), its weight, and an ADR in `docs/adr/` if it changes a decision.
- Privacy is a feature: no analytics, no third-party requests, no external fonts or scripts. The end-to-end privacy test must stay green.
- Never describe the product as removing protections or unlocking PDFs.

## How

```bash
pnpm install
pnpm lint && pnpm typecheck && pnpm test   # and `pnpm e2e` if the interface changed
```

Work on a branch, use Conventional Commits (the hook checks them), and open a pull request; CI runs everything, including three browsers. Every user-facing string goes in both `es.ts` and `en.ts`. Fixtures are generated by code or public domain, with their provenance in `tests/fixtures/README.md`.

## Conduct

Be kind and assume good faith. Harassment or discrimination of any kind is not welcome; maintainers may remove comments or contributions that cross that line. To report a problem, write to vidotho@gmail.com.
