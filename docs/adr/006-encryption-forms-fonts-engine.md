# ADR 006: Encryption, forms, fonts and stamping engine

- Status: Accepted
- Date: 2026-10-09
- Phase: 4

## Context

Phase 4 needs passwords, form filling, text that works beyond Latin-1, cropping and bookmarks. SPEC asks for a spike before choosing, and for every new piece to have its license verified ([ADR 016](016-legal-and-licensing-framework.md)). Every claim below was measured in code on 2026-10-09 with `@cantoo/pdf-lib` 2.11.1, `pdfjs-dist` 6.4 and `qpdf` 12.4 as the independent checker.

## What was measured

| Question                                       | Result                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ---------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Does `@cantoo/pdf-lib` encrypt?                | Yes: `doc.encrypt()` writes AES-256 (R6) by default; RC4 and AES-128 need an explicit `allowWeakCryptography`. `qpdf --check` accepts it and `--show-encryption` shows the permissions asked for.                                                                                                                                                                                                                                                                          |
| Is the result protected for a separate reader? | Yes: pdf.js raises `PasswordException` with no password and with a wrong one, and opens with the user or the owner password.                                                                                                                                                                                                                                                                                                                                               |
| Open an encrypted file                         | `PDFDocument.load(bytes, { password })`. A wrong password throws `Password incorrect`; none throws a message that starts "Input document ... is encrypted". Both are strings, so pdf.js's typed `PasswordException` is used to decide when to ask. An owner-restricted file with an empty user password opens with `{ password: '' }`.                                                                                                                                     |
| **What happens to restrictions on export?**    | **They are silently dropped.** After a file is opened with its password, `isEncrypted` is false and a page copied into a new document carries no encryption: the output is unprotected, with no restriction, no warning. This is the legal risk of ADR 016. The original `/P` permission value is still readable by loading with `ignoreEncryption: true` (-3904 in the fixture).                                                                                          |
| Forms through `copyPages`                      | The widgets are copied but the output has **no fields** (0). Rebuilding the AcroForm `/Fields` array from the copied widgets' top-level parents restores them (`full_name` text field and the checkbox come back, `qpdf --check` clean). This also fixes the v1 limitation "forms stop being fillable after merging".                                                                                                                                                      |
| Bookmarks                                      | pdf-lib has no outline API. Writing `/Outlines` by hand works: pdf.js reads nested items and a title with `ñ` and `—`; `qpdf --check` clean.                                                                                                                                                                                                                                                                                                                               |
| Crop                                           | `setCropBox` makes pdf.js draw only the box (150 x 250 for a 300 x 400 page). **The content outside is still in the file** (`qpdf --qdf` finds the text). Cropping hides, it does not remove.                                                                                                                                                                                                                                                                              |
| Custom fonts                                   | pdf-lib needs `@pdf-lib/fontkit` (MIT, one dependency, `pako`, MIT). It cannot read WOFF2 or variable fonts. It reads WOFF 1 but then embeds the **WOFF bytes as the font program, which is invalid**: pdf.js reports a missing `loca` table. Unwrapping the WOFF to its TrueType tables first (zlib, about 40 lines, `fflate` is already shipped) gives a valid font. Subsetting fails on the static Inter files, so the whole file is embedded (30 to 35 KB per script). |
| Font permission                                | Inter's embedding flags: `noEmbedding: false`, `viewOnly: false`, `editable: false`: embedding is allowed. The OFL FAQ allows embedding in documents.                                                                                                                                                                                                                                                                                                                      |
| Scripts                                        | Each Inter subset file (latin, latin-ext, cyrillic, greek, vietnamese) lacks the digits and punctuation of the others: Cyrillic text showed digits as missing-glyph boxes. Text needs per-character fallback across the files.                                                                                                                                                                                                                                             |

## Decision

1. **Engine:** keep `@cantoo/pdf-lib` for writing and `pdfjs-dist` for reading, drawing and checking. No qpdf in the app (ADR 005).
2. **Passwords:** AES-256 only. Choosing a password is the user's act; nothing is stored. Wrong or missing passwords are detected with pdf.js's `PasswordException`.
3. **Restrictions are never lifted.** Before opening, the original `/P` is read. Whatever is exported from a restricted source gets the **intersection** of the permissions of every restricted source, encrypted again, with a **random owner password that is thrown away**. If the user also sets an opening password, it is added on top. When restrictions are inherited, the user cannot choose an owner password, because whoever knew it could lift the restrictions of the source from the output. There is no feature to open or export with the owner password in this version, and the interface never talks about removing protection. A test reopens the output and checks the permissions against the source.
4. **Fonts:** `@pdf-lib/fontkit` and Inter 400 and 700 (OFL, from `@fontsource/inter`) loaded **only in the export worker, only when a step needs text**, so the initial download does not grow. A small function unwraps WOFF to TrueType. Per-character fallback across latin, latin-ext, cyrillic, greek and vietnamese. Characters no file covers (for example CJK) are refused with a message that names them; nothing is replaced silently by a box.
5. **Forms:** rebuild `/Fields` (and carry `/DR`, `/DA`) after copying pages, so forms survive merging. XFA is detected and reported as unsupported. Filling writes values and, if asked, flattens.
6. **Bookmarks:** written by hand from a tree in the workspace, with destinations mapped to the exported page positions; the source outlines are imported and kept when merging.
7. **Crop:** `setCropBox`, with the warning that content outside the box stays in the file.
8. **Metadata:** documents are created without pdf-lib's automatic producer and date stamps.

## Alternatives rejected

- **qpdf-wasm** for encryption and restrictions: no license text for qpdf and its compiled dependencies in the npm package (SPEC), and a second engine.
- **Dropping restrictions on request** with an "owner password" field: needs a check of the owner password that pdf-lib does not expose, which means writing the cryptographic check ourselves, and it is exactly the feature ADR 016 keeps out of scope.
- **Standard PDF fonts only:** WinAnsi covers Spanish and English but fails with Cyrillic, Greek, Vietnamese or most of Eastern Europe, and the viewer substitutes the font.
- **A larger font** (Noto Sans) for everything: a second family to license and ship; Inter is already the interface font.

## Consequences

- New dependencies: `@pdf-lib/fontkit` (MIT) with `pako` (MIT), and `@fontsource/inter` (OFL). `THIRD_PARTY_LICENSES.md`, the Licenses page and the SBOM are regenerated with them.
- Block 7 (passwords) is the only one that changes what happens to restricted files; it ships with the test of decision 3 and the register entry closed except for the owner's actions.
- Limits to document: no CJK in stamped text, XFA forms unsupported, cropping does not delete.
